# 상품코드 전환상품 매핑 편집 모달 요구사항

작성일: 2026-06-29

## 1. 목적

상품코드 페이지에서 전환상품도 세트상품처럼 상단 U상품 헤더 클릭으로 전체 매핑을 확인하고 편집할 수 있게 한다.

현재 세트상품은 헤더 클릭 시 `세트상품 구성 편집` 모달에서 전체 옵션 구성을 검토하고 수정할 수 있다. 반면 전환상품은 교차셀 직접 조작으로만 매핑을 설정한다. 같은 U상품 축에 있는 두 업무 정의의 편집 진입 방식이 달라 사용자가 일관된 모델로 이해하기 어렵다.

전환상품 모달의 목적은 교차셀 편집을 대체하는 것이 아니라, 전환상품의 모든 옵션별 1:1 매핑을 한 화면에서 검토하고 정리할 수 있는 전체 편집 경로를 제공하는 것이다.

## 2. 핵심 업무 규칙

전환상품은 `U상품/옵션 -> L상품/옵션` 간 1:1 매핑이다.

- U상품 옵션 1개는 최대 1개의 L상품/옵션에 매핑된다.
- 세트상품처럼 한 옵션이 여러 L상품 구성품을 가질 수 없다.
- L상품이 옵션을 가진 경우에는 L상품 코드뿐 아니라 L옵션 코드까지 명확히 선택해야 한다.
- 매핑이 없으면 해당 U옵션은 `미매핑` 상태다.
- 전환수량은 기본 1이다. 수량 필드를 제공하더라도 기본 의미는 1:1 전환이며, 다중 구성품 입력과 혼동되면 안 된다.

## 3. 현재 문제

### 3.1 편집 진입 방식 불일치

- 세트상품: U상품 헤더 클릭으로 전체 구성 편집 모달 진입.
- 전환상품: 교차셀 직접 편집으로만 매핑 변경 가능.

사용자는 같은 상단 U상품 축에서 세트상품과 전환상품을 보지만, 편집 방식이 달라진다. 이는 UI 일관성을 해치며, 전환상품 전체 매핑을 검토해야 할 때 반복적으로 교차셀을 찾아야 한다.

### 3.2 전체 매핑 검토 어려움

전환상품은 옵션별 매핑이 핵심이다. 현재 방식은 특정 교차셀을 찾아 조작하는 데는 적합하지만, 한 U상품의 모든 옵션이 어디에 매핑되어 있는지 한눈에 보기 어렵다.

특히 아래 상황에서 문제가 된다.

- U옵션 중 일부가 미매핑인지 확인할 때
- 잘못된 L상품/옵션으로 연결된 항목을 찾을 때
- 상품명과 옵션명을 함께 확인해야 할 때
- 교차셀 위치가 멀리 떨어져 있어 스크롤이 많이 필요한 경우

### 3.3 상품명/옵션명 정보 부족

전환상품 매핑은 코드만으로 판단하면 오류 가능성이 크다. 모달에서는 U상품명, U옵션명, L상품명, L옵션명을 모두 보여줘야 한다.

## 4. 요구사항

### 4.1 진입점

- 전환상품 U상품 헤더를 클릭하면 `전환상품 매핑 편집` 모달이 열린다.
- 세트상품 헤더 클릭은 기존처럼 `세트상품 구성 편집` 모달을 연다.
- 전환상품 교차셀 더블클릭을 통한 기존 빠른 매핑 변경 흐름은 유지한다.

### 4.2 모달 기본 정보

모달 상단에는 아래 정보를 표시한다.

- 전환상품명
- 전환상품 코드
- 옵션 개수
- 변경 여부 표시

### 4.3 U옵션 목록 표시

모달은 해당 전환상품의 모든 U옵션을 행으로 표시한다.

각 행에는 아래 정보가 반드시 보여야 한다.

- U옵션 코드
- U옵션명
- 현재 매핑된 L상품 코드
- 현재 매핑된 L상품명
- 현재 매핑된 L옵션 코드
- 현재 매핑된 L옵션명
- 전환수량
- 상태: 매핑됨 / 미매핑 / 변경됨 / 삭제 예정

상품명과 옵션명은 생략하지 않는다. 화면 폭 때문에 줄임 표시가 필요하더라도 title 또는 확장 영역으로 전체 값을 확인할 수 있어야 한다.

### 4.4 L상품/옵션 선택

각 U옵션 행에서 매핑할 L상품/옵션을 선택할 수 있어야 한다.

- L상품 선택 목록에는 선택 가능한 모든 L상품 코드와 상품명이 표시된다.
- L상품 선택 후, 해당 L상품의 모든 L옵션 코드와 옵션명이 표시된다.
- 단일 옵션 상품도 옵션 코드/옵션명을 명확히 보여준다.
- L상품을 바꾸면 L옵션 선택지는 해당 상품 기준으로 갱신된다.
- L상품/옵션을 비우면 해당 U옵션은 `미매핑` 상태가 된다.

### 4.5 1:1 매핑 제약

- 한 U옵션 행에는 L상품/옵션 선택 조합이 하나만 존재한다.
- 행 안에서 여러 L상품을 추가하는 UI를 제공하지 않는다.
- 세트상품 모달의 `왼쪽상품 추가` 같은 기능은 전환상품 모달에 두지 않는다.
- 같은 U상품/옵션에 여러 활성 매핑이 생기면 안 된다.

### 4.6 적용/취소/초기화

- `적용`: 화면 초안을 실제 매핑 상태에 반영한다.
- `취소`: 모달에서 변경한 내용을 버리고 닫는다.
- `초기값`: 해당 전환상품의 매핑을 기본 정의 상태로 되돌린다.
- 변경 전까지는 화면 계산과 교차셀에 반영하지 않는다.
- 적용 후 교차셀, 합계, 매출, 수식 설명, Excel 다운로드가 같은 결과를 사용해야 한다.

### 4.7 기존 교차셀 편집과의 관계

- 교차셀 더블클릭은 특정 U옵션과 L상품/옵션 간 빠른 매핑 변경 경로로 유지한다.
- 모달은 U상품 단위 전체 매핑 편집 경로다.
- 두 경로는 같은 매핑 원천/override 상태를 사용해야 한다.
- 한쪽에서 변경한 결과가 다른 쪽 UI와 계산 결과에 즉시 일관되게 반영되어야 한다.

## 5. UX 원칙

- 같은 U상품 헤더 클릭은 항상 해당 U상품의 업무 정의를 편집하는 진입점이어야 한다.
- 세트상품과 전환상품은 외형과 조작 패턴을 맞추되, 업무 용어는 분리한다.
  - 세트상품: 구성
  - 전환상품: 매핑
- 전환상품 모달은 `구성품 추가`가 아니라 `옵션별 1:1 매핑 선택`에 집중한다.
- 코드만 보게 만들지 않고 모든 상품명/옵션명을 함께 보여준다.
- 미매핑 상태는 오류처럼 숨기지 않고, 사용자가 다음 행동을 알 수 있게 표시한다.

## 6. 데이터 무결성 요구사항

- 동일 U상품/옵션에 활성 매핑이 2개 이상 생기면 안 된다.
- L상품 옵션이 있는 상품은 L옵션 없이 저장하면 안 된다.
- 미매핑 상태는 계산에서 제외되어야 한다.
- 매핑 변경 후 화면 교차셀 수량, 총판매, 매출, 합계, 수식 설명, Excel 다운로드가 모두 동일한 매핑 상태를 사용해야 한다.
- 변경 초안과 적용 완료 상태가 구분되어야 한다.

## 7. 검증 기준

### 7.1 정상 흐름

1. 전환상품 헤더 클릭 시 `전환상품 매핑 편집` 모달이 열린다.
2. 모달에는 해당 U상품의 모든 옵션 코드와 옵션명이 표시된다.
3. 각 U옵션 행에는 현재 매핑된 L상품/옵션 코드와 이름이 표시된다.
4. L상품을 변경하고 L옵션을 선택한 뒤 적용하면 교차셀 위치와 합계가 갱신된다.
5. 적용 후 다시 모달을 열면 변경된 매핑이 유지되어 보인다.

### 7.2 비정상/오류 흐름

1. L상품만 선택하고 L옵션을 선택하지 않은 행은 적용할 수 없다.
2. 미매핑으로 둔 U옵션은 교차셀/합계/매출 계산에서 제외된다.
3. 취소를 누르면 변경 전 상태가 유지된다.
4. 초기값을 누르면 기본 매핑 정의로 되돌아간다.
5. 존재하지 않는 L상품/옵션 메타데이터가 있으면 사용자가 이해 가능한 미확인 상태를 표시한다.

### 7.3 회귀/E2E

1. 전환상품 헤더 클릭 모달 진입 E2E.
2. 모든 U옵션명 표시 E2E.
3. 모든 L상품명/L옵션명 선택 가능 E2E.
4. 1:1 매핑 변경 후 교차셀 이동/합계 반영 E2E.
5. 매핑 삭제 후 계산 제외 E2E.
6. 취소 시 변경 미반영 E2E.
7. Excel 다운로드 반영 E2E.
8. 기존 교차셀 더블클릭 매핑 변경 회귀 E2E.

## 8. 구현 전 결정 필요사항

1. 전환수량 필드를 UI에 노출할지 여부.
   - 기본은 1:1이므로 숨기거나 읽기 전용으로 시작하는 방안이 유력하다.
2. 미매핑을 `삭제` 버튼으로 표현할지, L상품 선택값을 비우는 방식으로 표현할지.
3. 기본 매핑 정의와 사용자 override를 화면 상태에만 둘지, DB 원천화 설계와 맞춰 저장할지.
4. 세트상품 모달과 동일한 드래그/리사이즈 기능을 1차 구현에 포함할지.
