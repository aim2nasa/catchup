# 상품코드 계산식 해설 UI 설계

작성일: 2026-06-25

## 1. 목적

상품코드 페이지에서 수식이 계산되는 셀을 선택했을 때, 사용자가 원문 수식을 해석하지 않아도 값이 왜 나왔는지 바로 이해할 수 있게 한다.

현재 예시는 아래와 같다.

```text
=F11*E11+BG11*세트 구성 단가[P00000YS/A->P00000HT/A]
```

이 수식은 데이터 무결성과 Excel 추적성에는 필요하지만, 사용자 관점에서는 `F11`, `E11`, `BG11`, `세트 구성 단가[...]`가 무엇을 뜻하는지 즉시 알기 어렵다. 따라서 원문 수식은 유지하되, 기본 UI는 사람이 읽을 수 있는 계산 해설을 먼저 보여준다.

## 2. 적용 범위

적용 대상은 특정 열이 아니라 `상품코드` 페이지에서 수식이 계산되는 모든 셀이다.

- 직접판매 합계
- 총판매
- 교차셀 합계
- 매출
- 카테고리 합계
- 구간 합계
- 전체 합계
- 전환 단가 참조가 들어간 계산
- 세트 구성 단가 참조가 들어간 계산
- 향후 추가되는 모든 계산식 셀

수식 없는 단순 값 셀은 계산 해설 대상이 아니다.

## 3. 핵심 원칙

1. 원문 수식은 유지한다.
2. 사용자에게는 원문 수식보다 계산 해설을 먼저 보여준다.
3. 수식 문자열을 파싱해서 해설을 만들지 않는다.
4. 화면 표시 수식, Excel 다운로드 수식, 사용자용 계산 해설은 같은 계산 원천에서 생성한다.
5. 같은 계산 의미는 화면 어디서나 같은 용어와 같은 UI 패턴으로 표시한다.
6. 해설의 항목 합계는 실제 셀 값과 일치해야 한다.
7. Hawkeye 기준으로, 사용자가 다른 문서나 모달을 찾아다니지 않아도 1차 계산 의미를 이해할 수 있어야 한다.

## 4. 계산 해설 모델

수식 생성 결과는 `display`, `excel`에 더해 `explanation`을 가진다.

```ts
type FormulaExplanation = {
  title: string
  resultLabel?: string
  summary: string
  terms: FormulaExplanationTerm[]
  sourceFormula: string
}
```

계산 항목은 업무 의미를 기준으로 분류한다.

```ts
type FormulaExplanationTerm =
  | DirectSalesTerm
  | ConversionTerm
  | SetComponentTerm
  | SumTerm
  | ReferenceTerm
```

각 항목은 최소한 아래 정보를 제공한다.

- 구분
- 참조 셀 또는 참조 범위
- 상품/옵션 맥락
- 수량
- 단가
- 금액 또는 합계

## 5. UI 표시 방식

기본 위치는 기존 상단 선택 정보 영역이다. 모달을 기본으로 쓰지 않는다.

이유:

- 계산 해설은 셀을 바꿔가며 반복 확인하는 흐름이다.
- 모달은 표와 선택 셀을 가려 비교 흐름을 방해한다.
- 상단 고정 영역은 현재 선택 셀과 표를 동시에 유지할 수 있다.

표시 구조:

1. 선택 좌표와 계산 제목
2. 한 줄 요약
3. 계산 항목 목록
4. 원문 수식 접힘 영역

원문 수식은 `원문 수식` 보조 영역으로 낮은 위계에 둔다.

## 6. 대표 표시 예

### 6.1 매출 셀

셀: `BL11`

요약:

```text
직접판매 매출 ₩1,972,500 + 세트 구성 매출 ₩42,080 = ₩2,014,580
```

항목:

| 구분 | 계산 | 금액 |
|---|---|---:|
| 직접판매 | 직접판매 75 × 단가 ₩26,300 | ₩1,972,500 |
| 세트 구성 | 제모미인 스타터키트20% A 판매 2 × P00000HT/A 세트 구성 단가 ₩21,040 | ₩42,080 |

원문 수식:

```text
=F11*E11+BG11*세트 구성 단가[P00000YS/A->P00000HT/A]
```

### 6.2 전환 단가 매출 셀

요약:

```text
직접판매 매출 ₩131,500 + 전환상품 매출 ₩0 = ₩131,500
```

항목에는 전환상품, 위쪽 옵션, 왼쪽 상품/옵션, 전환 단가를 함께 표시한다.

### 6.3 합계 셀

요약:

```text
하위 500g 행 23개 합계 = ₩10,280,540
```

항목:

- 합산 범위
- 합산 대상 행 수
- 결과

## 7. Hawkeye PASS 기준

- 사용자가 수식 셀을 클릭했을 때 값이 왜 나왔는지 상단 영역만 보고 이해할 수 있다.
- 내부 참조명은 상품명, 옵션명, 수량, 단가로 풀려 보인다.
- 모든 수식 셀은 같은 해설 패턴을 사용한다.
- 원문 수식은 계속 확인 가능하지만 기본 정보보다 앞서지 않는다.
- 해설 총액과 셀 값이 다르면 FAIL이다.
- 좁은 화면에서도 해설 영역이 표 조작을 방해하지 않는다.

## 8. 구현 플랜

### Phase 1: 해설 모델 추가

- `FormulaBuildResult`에 `explanation`을 추가한다.
- 직접판매, 전환상품, 세트상품 구성, 합계 수식을 만들 때 해설 항목을 함께 만든다.

완료 기준:

- 기존 수식 표시와 Excel 수식은 유지된다.
- `rowFormulaByKey`에서 모든 수식 셀의 해설을 조회할 수 있다.

### Phase 2: 상단 해설 UI 추가

- 기존 `수식` 표시를 계산 해설 패널로 바꾼다.
- 원문 수식은 보조 영역으로 표시한다.

완료 기준:

- `BL11`, `BL12`, `BK`, 합계행 셀에서 해설이 표시된다.
- 수식 없는 셀에는 해설 패널이 표시되지 않는다.

### Phase 3: 회귀 테스트

- 매출 셀의 직접판매 + 세트 구성 해설
- 매출 셀의 전환 단가 해설
- 총판매 셀 해설
- 합계행 셀 해설
- 원문 수식 유지
- Excel 다운로드 수식/값 무결성 기존 테스트 유지

완료 기준:

- E2E에서 정상/대표 계산 흐름이 통과한다.
- 기존 Excel 동적 대조 테스트가 계속 통과한다.

## 9. 구현 시 주의사항

- 수식 문자열 정규식 파싱을 해설의 주 데이터 원천으로 쓰지 않는다.
- 기존 `splitFormulaForDisplay`는 원문 수식 보조 표시 용도로만 남긴다.
- 설명 항목의 금액은 실제 셀 값과 같은 계산 경로를 사용한다.
- 문구는 개발자 용어보다 사용자 업무 용어를 우선한다.
