# 상품코드 페이지 Cafe24 조회값 상태 적용 설계 결정

## 목적

`docs/cafe24-read-value-state-policy.md`의 정책을 `상품코드` 페이지에 먼저 적용하기 위한 설계 결정 문서다.

이 문서는 구현 전 결정해야 하는 표시, 계산, Excel 다운로드, 검증 범위를 확정하기 위한 초안이다. 사용자 검토 후 승인된 항목만 구현한다.

## 참조 요구사항

- 요구사항 인박스: `REQ-20260624-01: Cafe24 조회값의 0/확인불가/기준값 상태를 보존한다`
- 정책 문서: `docs/cafe24-read-value-state-policy.md`

## 적용 범위 결정

### 결정안

1차 구현 범위는 `상품코드` 페이지로 제한한다.

포함:

- `ProductCodesView`
- 상품코드 페이지의 L상품 행
- 상품코드 페이지의 U/L 매핑 셀
- 상품코드 페이지의 직접판매, 총판매, 매출
- 상품코드 페이지의 소계/합계
- 상품코드 페이지의 Excel 다운로드
- 관련 E2E 테스트

제외:

- `하드왁스` 페이지 공통 모델 전면 개편
- 백엔드 Cafe24 수집 API 계약 변경
- 다른 집계 페이지의 Excel 다운로드 구조 변경

### 이유

현재 문제는 상품코드 페이지의 L상품 추가 중 발견되었다. 공통 모델까지 한 번에 확장하면 범위가 커지고 기존 하드왁스 화면에 영향을 줄 수 있다. 상품코드 페이지에서 상태 모델을 먼저 검증한 뒤 공통화 여부를 결정한다.

## 값 상태 모델

### 결정안

상품코드 페이지 내부에서 조회 기반 셀 값을 아래 상태로 관리한다.

```ts
type ReadStatus = 'loaded' | 'missing' | 'fallback' | 'partial' | 'calculated'
type ReadSource = 'cafe24' | 'set-design' | 'local-rule' | 'calculated'

type ReadCellValue<T> = {
  value: T | null
  status: ReadStatus
  source: ReadSource
  note?: string
}
```

### 상태 적용

| 값 종류 | 상태 |
|---|---|
| Cafe24 응답에서 읽은 값 | `loaded`, `source='cafe24'` |
| 기준표에 존재하는 상품/옵션이 Cafe24 기간 판매 응답에 없음 | `loaded`, `source='set-design'`, `value=0` |
| 상품/옵션 존재 기준이 없거나 필수 필드 확인 불가 | `missing`, `source='cafe24'` |
| `세트할인 구조설계` 기준으로 보강한 상품명/옵션명/단가 | `fallback`, `source='set-design'` |
| 조회값만으로 계산된 총판매/매출/소계/합계 | `calculated`, `source='calculated'` |
| 일부 확인불가가 제외된 계산값 | `partial`, `source='calculated'` |

### 구현 메모

현재 `Row` 구조는 숫자 배열 중심이다. 1차 구현에서는 전체 공통 타입을 뒤집기보다 상품코드 페이지 내부에서 상태 메타 배열을 병행한다.

예:

- `directQtyStatus`
- `variantDirectQtyStatus[]`
- `mappingStateByColumn[]` 확장
- `subtotalStatus`
- `revenueStatus`

## 화면 표시 결정

### 확인불가 표시

결정안:

- 좁은 숫자 셀: `미`
- tooltip/선택 패널: `확인불가`
- tooltip 문구: `상품/옵션 존재 기준을 확인할 수 없어 0으로 해석하지 않음.`

이유:

- `0`과 즉시 구분된다.
- `-`보다 의미가 명확하다.
- `확인불가`보다 좁은 셀에 적합하다.
- `?`보다 업무용 표에서 덜 가볍다.

### 실제 0 표시

Cafe24에서 읽은 실제 0과 기준표에서 존재가 확인된 상품/옵션의 기간 응답 누락은 그대로 `0`으로 표시한다.

조건:

- `status='loaded'`
- `source='cafe24'` 또는 `source='set-design'`
- `value=0`

### 기준표 보강값 표시

상품명, 옵션명, 단가는 기준표 값으로 표시할 수 있다.

표시:

- 셀 값: 기준표 값 그대로 표시
- tooltip/선택 패널: `기준표 값`

주의:

- 기준표 보강값은 Cafe24 조회값이 아니다.
- 단가를 계산에 사용할지 여부는 아래 계산 정책을 따른다.

### 확인불가 스타일

결정안:

- 배경: 연한 노랑 또는 연회색
- 글자색: 진한 회색 또는 갈색
- 테두리: 기존 표 선을 유지하되, 선택/hover와 충돌하지 않게 최소화

금지:

- 강한 빨강 배경
- 행 전체 경고색
- 숫자처럼 보이는 대체값

## 계산 정책 결정

### 직접판매

| 상태 | 표시 | 계산 |
|---|---|---|
| Cafe24 조회값 있음 | 숫자 | 포함 |
| Cafe24 조회값 0 | `0` | 포함 |
| 기준표 존재 확인 + 기간 응답 없음 | `0` | 포함 |
| 확인불가 | `미` | 제외 |

### 총판매

총판매는 직접판매와 매핑 수량을 합산한 값이다.

결정안:

- 모든 입력이 조회됨/계산 가능: 숫자 표시
- 일부 입력 확인불가: 조회/기간 판매 없음 값만 합산하고 `partial` 상태 부여
- 화면 표시: `숫자*`
- tooltip/선택 패널: `확인불가 항목 제외 합계`

### 매출

매출은 수량과 단가가 모두 계산 가능한 경우에만 계산한다.

결정안:

- 수량과 단가가 모두 Cafe24 조회값 또는 계산 허용 기준값이면 계산
- 수량이 확인불가이면 해당 행 매출은 `미`
- 단가가 확인불가이면 해당 행 매출은 `미`
- 기준표 단가는 1차 구현에서 계산에 사용할 수 있다. 단, 상태는 `fallback` 또는 `partial`로 전파한다.

기준표 단가 사용 조건:

- `세트할인 구조설계` 탭에 명시된 단가인 경우
- 해당 상품/옵션 식별이 명확한 경우
- 화면/Excel에서 기준표 단가임을 보존하는 경우

### 소계/합계

결정안:

- 확인불가 없이 계산된 경우: 숫자만 표시
- 확인불가 포함 계산: `숫자*`
- tooltip/선택 패널: `확인불가 항목 제외 합계`
- Excel: 상태를 `확인불가 제외 합계`로 보존

## Excel 다운로드 결정

### 기본 방향

Excel에서는 계산 안정성을 위해 값과 상태를 분리한다.

화면의 좁은 셀 표시는 Excel에 그대로 복제하지 않는다. Excel 파일만 열어도 상태 맥락을 이해할 수 있게 별도 상태 정보와 범례를 제공한다.

### 컬럼 구조

결정안:

기존 표의 주요 좌표계는 유지한다. 상태 컬럼을 중간에 삽입해 기존 컬럼을 밀지 않는다.

대신 다음 방식을 사용한다.

1. 숫자/금액 셀
   - 조회된 값: 숫자
   - 확인불가 값: 빈값
2. 셀 주석
   - 확인불가 셀: `상품/옵션 존재 기준을 확인할 수 없어 0으로 해석하지 않음.`
   - 기준표 보강 셀: `세트할인 구조설계 기준값`
   - 확인불가 포함 합계: `확인불가 항목 제외 합계`
3. 범례 영역
   - 시트 상단 또는 하단에 상태 의미를 명시
4. 상태 요약 영역
   - 확인불가 항목 수
   - 기준표 보강 항목 수
   - 확인불가 포함 합계 존재 여부

### 이유

상태 컬럼을 중간에 삽입하면 기존 Excel 좌표계와 수식 참조가 크게 바뀐다. 현재 상품코드 페이지는 엑셀 좌표계 유지 요구가 강하므로, 1차 구현에서는 좌표계를 유지하고 주석/범례/상태 요약으로 맥락을 보존한다.

### 확인불가 Excel 값

| 화면 상태 | Excel 값 셀 | Excel 상태 보존 |
|---|---|---|
| 실제 0 | `0` | 필요 시 주석 없음 |
| 기준표 존재 확인 + 기간 응답 없음 | `0` | 필요 시 기간 판매 없음 주석 또는 범례 |
| 확인불가 | 빈값 | 셀 주석 + 범례 |
| 기준표 값 | 값 | 셀 주석 또는 상태 요약 |
| 확인불가 포함 합계 | 조회/기간 판매 없음 값의 합계 | 셀 주석 + 범례 |

## 기존 좌표계 유지 결정

결정안:

- 화면 좌표계와 Excel 주요 데이터 좌표는 유지한다.
- 상태 정보를 위해 기존 데이터 컬럼 사이에 새 컬럼을 삽입하지 않는다.
- 범례/상태 요약은 표 바깥 영역에 둔다.
- 확인불가/기준표 상태는 셀 주석, 스타일, 범례로 보존한다.

열 삽입이 필요해지는 경우는 별도 승인 후 진행한다.

## E2E 검증 매트릭스

### 정상 흐름

1. Cafe24 조회값이 있는 L상품은 직접판매/총판매/매출을 숫자로 표시한다.
2. Cafe24 조회값이 실제 0인 셀과 기준표 존재 확인 후 기간 응답에 없는 셀은 `0`으로 표시한다.
3. 기준표 보강 상품명/옵션명/단가는 화면에 표시된다.
4. Excel 다운로드가 정상 생성된다.

### 기간 판매 없음 흐름

1. 기준표에 존재하는 상품/옵션이 Cafe24 기간 판매 응답에 없으면 직접판매를 `0`으로 표시한다.
2. 해당 매출은 `0 x 단가 = 0`으로 계산한다.
3. 총판매/소계/합계는 확인불가가 섞이지 않으면 숫자만 표시한다.
4. Excel 다운로드에서도 숫자 `0`으로 유지한다.

### 확인불가 흐름

1. 상품/옵션 존재 기준이 없거나 API 실패/응답 중단이면 직접판매를 `미`로 표시한다.
2. 해당 매출은 `미`로 표시한다.
3. 총판매/소계/합계는 `숫자*`로 표시한다.
4. tooltip 또는 선택 메타에 `확인불가 항목 제외 합계`가 남는다.
5. Excel 다운로드에서 확인불가 셀은 빈값이고 주석/범례가 존재한다.

### 기준표 보강 흐름

1. Cafe24 응답이 없어도 기준표 상품명/옵션명/단가는 표시된다.
2. 기준표 값은 Cafe24 조회값으로 오해되지 않도록 주석/상태가 남는다.
3. 기준표 단가로 계산한 매출은 상태가 전파된다.

### Excel 계산 흐름

1. Excel 숫자 셀에 텍스트 `확인불가`가 들어가지 않는다.
2. SUM 계열 수식이 깨지지 않는다.
3. 확인불가 항목이 0으로 합산되지 않는다.
4. Excel만 열어도 `0`, 기간 판매 없음, 확인불가, 기준표 값, 확인불가 제외 합계의 의미를 이해할 수 있다.

### 회귀 흐름

1. 기존 하드왁스 페이지 수평 스크롤 동작이 깨지지 않는다.
2. 상품코드 페이지 수평 스크롤 중 매출 컬럼 폭이 유지된다.
3. 기존 상품코드 페이지 카테고리/좌표 행 구조가 깨지지 않는다.

## 구현 배치 제안

### Batch 1: 상품코드 페이지 화면 상태 적용

- 상품코드 페이지 내부 상태 모델 추가
- 확인불가/기준표/부분합계 화면 표시
- 선택/tooltip 메타 보강
- 화면 E2E 추가

### Batch 2: 상품코드 Excel 다운로드 상태 보존

- 확인불가 셀 빈값 처리
- 주석/범례/상태 요약 추가
- 확인불가 포함 합계 주석 추가
- Excel E2E 추가

### Batch 3: 공통화 검토

- 상품코드 페이지 적용 결과 검토
- 하드왁스 페이지 및 공통 모델 확장 여부 결정

## 승인 필요 항목

구현 전 아래 결정을 사용자에게 확인한다.

1. 화면 확인불가 표시를 `미`로 진행해도 되는가?
2. 1차 Excel 구현에서 상태 컬럼 삽입 없이 주석/범례/상태 요약으로 진행해도 되는가?
3. 기준표 단가를 매출 계산에 사용하되 `fallback/partial` 상태를 전파하는 방식으로 진행해도 되는가?
4. 적용 범위를 상품코드 페이지로 제한하고, 하드왁스 페이지 공통화는 후속 배치로 미뤄도 되는가?
