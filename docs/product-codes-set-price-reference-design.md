# 상품코드 세트 구성 단가 참조 설계

작성일: 2026-06-25

## 1. 목적

상품코드 페이지의 `매출` 열 수식에서 세트상품 구성 단가를 숫자 literal로 직접 박지 않고, 사용자가 출처를 추적할 수 있는 참조값으로 표현한다.

예를 들어 현재 `BL11` 수식은 아래처럼 표시된다.

```excel
=F11*E11+BG11*21040
```

여기서 `21040`은 엑셀 그리드에 보이는 값이 아니라, 세트상품 구성 편집 모달에 정의된 `P00000YS / A -> P00000HT / A`의 세트가다. 이 값이 수식 안에 숫자로만 들어가면 사용자는 출처를 알기 어렵고, 세트가가 바뀌었을 때 수식과 다운로드 엑셀의 동기화 여부를 검증하기 어렵다.

이 설계의 목표는 아래 세 가지다.

- 화면 수식에서 세트 구성 단가의 출처를 사용자가 이해할 수 있다.
- Excel 다운로드 파일에서도 단가 출처와 계산식이 보존된다.
- 세트상품 구성 편집 모달의 값 변경이 화면 계산, 수식 표시, Excel 다운로드에 일관되게 반영된다.

## 3. 현재 문제

### 3.1 수식 추적성 부족

현재 매출 수식은 세트 구성 단가를 숫자 literal로 표시한다.

```excel
=F11*E11+BG11*21040
```

사용자는 `21040`이 어떤 세트상품, 어떤 옵션, 어떤 왼쪽상품 구성에서 나온 값인지 수식만 보고 알 수 없다.

### 3.2 변경 동기화 위험

세트상품 구성 편집 모달에서 세트가를 수정할 수 있다. 그러나 수식이 숫자 literal처럼 보이면, 사용자는 수식이 모달 정의와 동기화되는지 확신하기 어렵다. Excel 다운로드 후에도 어떤 값을 수정해야 관련 매출 수식이 함께 바뀌는지 명확하지 않다.

### 3.3 직접판매 단가와 세트 구성 단가의 의미 혼동

직접판매 매출 항은 `직접판매 수량 * 일반 단가`다.

```excel
F11*E11
```

반면 세트상품 기여 매출 항은 `세트상품 구성 환산 수량 * 세트 구성 단가`다.

```excel
BG11*21040
```

두 단가는 원천과 업무 의미가 다르다. 수식에 숫자만 있으면 이 차이가 드러나지 않는다.

## 4. 설계 원칙

1. 세트 구성 단가의 단일 원천은 세트상품 구성 데이터다.
2. 화면 수식과 Excel 다운로드 수식은 같은 단가 원천을 참조한다.
3. Excel 파일만 열어도 단가의 출처와 값이 보존되어야 한다.
4. 사용자가 세트 구성 단가를 변경하면 관련 매출 계산이 일관되게 갱신되어야 한다.
5. 수식은 Excel에서 실제 계산 가능해야 한다.
6. 직접판매 단가와 세트 구성 단가는 표시와 참조 구조에서 구분되어야 한다.
7. 이름, 참조, 보조표는 같은 의미에 항상 같은 규칙을 사용한다.

## 5. 선택 설계안

### 5.1 최종 선택: 보조 시트 + 이름 정의 + 화면용 설명 수식

세트 구성 단가는 Excel 다운로드 시 별도 보조 시트에 표로 기록하고, 각 세트가 셀에 안정적인 Excel 이름 정의를 부여한다. BL 매출 수식은 숫자 literal 대신 이 이름을 참조한다.

화면 수식은 Excel 수식과 별도로 사용자가 이해하기 쉬운 설명을 함께 제공한다.

#### Excel 계산 수식 예

기존:

```excel
=F11*E11+BG11*21040
```

개선:

```excel
=F11*E11+BG11*SET_P00000YS_A_P00000HT_A_PRICE
```

#### 화면 설명 수식 예

```text
F11 x E11 + BG11 x 세트가(P00000YS/A -> P00000HT/A)
```

화면에는 사용자가 수식의 업무 의미를 이해할 수 있도록 `세트가(...)` 형태를 표시하고, Excel에는 실제 계산 가능한 이름 정의를 사용한다.

## 6. Excel 보조 시트 설계

### 6.1 시트명

권장 시트명:

```text
세트상품구성
```

이 시트는 기본적으로 표시한다. 숨김 시트는 추적성이 떨어지므로 1차 구현에서는 사용하지 않는다. 사용자가 보기 싫어할 경우 후속 옵션으로 숨김 처리 여부를 검토한다.

### 6.2 컬럼

| 컬럼 | 이름 | 설명 |
|---|---|---|
| A | 참조명 | Excel 이름 정의와 동일한 안정 ID |
| B | 세트상품코드 | 예: `P00000YS` |
| C | 세트상품옵션 | 예: `A` |
| D | 세트상품명 | 예: `제모미인 스타터키트20%` |
| E | 왼쪽상품코드 | 예: `P00000HT` |
| F | 왼쪽상품옵션 | 예: `A` |
| G | 왼쪽상품명 | 예: `라이코젯아이브로우...` |
| H | 왼쪽옵션명 | 예: `-` |
| I | 구성수량 | 예: `1` |
| J | 세트가 | 예: `21040` |
| K | 구성금액 | `=I행*J행` |
| L | 적용범위 | `공통` 또는 `옵션` |

### 6.3 이름 정의 규칙

Excel 이름은 다음 규칙으로 생성한다.

```text
SET_{세트상품코드}_{세트옵션}_{왼쪽상품코드}_{왼쪽옵션}_PRICE
```

예:

```text
SET_P00000YS_A_P00000HT_A_PRICE
```

규칙:

- 영문 대문자, 숫자, `_`만 사용한다.
- 옵션이 없거나 `-`인 경우 내부 canonical option code를 사용한다.
- Excel 셀 주소처럼 해석될 수 있는 이름은 피한다.
- 동일 이름 충돌이 발생하면 구성 id 기반 suffix를 붙인다.
- 이름 정의는 `세트상품구성!J행`의 세트가 셀을 참조한다.

## 7. 화면 표시 설계

### 7.1 상단 수식 표시

현재 상단 수식 표시에서 숫자 literal로 보이던 세트 구성 단가는 설명 토큰으로 바꾼다.

예:

```text
=F11*E11+BG11*세트가(P00000YS/A -> P00000HT/A)
```

토큰 hover 또는 클릭 시 다음 정보를 보여준다.

- 참조명: `SET_P00000YS_A_P00000HT_A_PRICE`
- 세트상품: `P00000YS / A`
- 왼쪽상품: `P00000HT / A`
- 구성수량: `1`
- 세트가: `₩21,040`
- 구성금액: `₩21,040`

### 7.2 모달과의 연결

세트상품 구성 편집 모달의 `세트가` 입력값은 동일한 단가 원천이다.

- 모달에서 세트가 변경
- 화면 교차셀 수량/매출 재계산
- BL 수식 설명 갱신
- Excel 다운로드 보조 시트 값 갱신
- Excel 이름 정의 참조 수식 유지

이 흐름이 하나의 데이터 경로로 연결되어야 한다.

## 8. 매출 수식 생성 규칙

### 8.1 직접판매 항

직접판매 항은 기존과 동일하다.

```excel
F{row}*E{row}
```

직접판매 단가는 L상품 기준 일반 단가이므로 기존 셀 참조를 유지한다.

### 8.2 전환상품 항

전환상품 항은 기존 방식의 U상품 단가 참조 정책을 따른다. 이 설계는 세트상품 구성 단가를 우선 대상으로 한다.

### 8.3 세트상품 항

세트상품 항은 숫자 literal 대신 세트 구성 단가 참조명을 사용한다.

```excel
{세트상품수량셀}*{세트구성단가참조명}
```

예:

```excel
BG11*SET_P00000YS_A_P00000HT_A_PRICE
```

### 8.4 수량이 0인 세트 구성

세트 구성 정의가 존재하면 수량이 0이어도 수식 항은 유지한다.

```excel
BG11*SET_P00000YS_A_P00000HT_A_PRICE
```

이는 `LU셀(교차점 매핑) 계약`의 “정의 존재 여부가 수식 항 포함 기준” 원칙과 일치한다.

## 9. 데이터 모델 영향

현재 매출 수식 생성에 필요한 `RevenueFormulaTerm`은 단가 숫자만 갖는 형태다. 구현 시 세트상품 항에는 다음 메타가 추가로 필요하다.

```ts
type RevenueFormulaTerm = {
  uColOffset: number
  unitPrice: number
  priceMissing?: boolean
  priceSource?: 'cafe24' | 'set-component'
  priceRefName?: string
  priceRefLabel?: string
  setComponentRef?: {
    setProductCode: string
    setOptionCode: string
    lProductCode: string
    lOptionCode: string
    qty: number
    setPrice: number
  }
}
```

이 타입은 예시이며, 실제 구현 시 기존 타입과 중복을 줄이는 방향으로 조정한다.

## 10. 대안 검토

### 대안 A: 숫자 literal 유지 + tooltip만 추가

- 장점: 구현이 가장 작다.
- 단점: Excel 다운로드 파일의 추적성 문제가 그대로 남는다.
- 판단: 요구사항을 충족하지 못한다.

### 대안 B: Excel 이름 정의만 사용

- 장점: 수식이 깔끔하다.
- 단점: 사용자가 이름의 출처를 찾기 어렵다.
- 판단: 보조 시트 없이 단독 사용은 부족하다.

### 대안 C: 보조 시트의 셀 주소 직접 참조

예:

```excel
=F11*E11+BG11*세트상품구성!J2
```

- 장점: Excel에서 출처를 바로 따라갈 수 있다.
- 단점: 수식이 길어지고 행 삽입/정렬/구조 변경에 취약하다.
- 판단: 이름 정의보다 안정성이 낮다. 보조 시트는 유지하되 수식은 이름 정의를 사용한다.

### 대안 D: 보조 시트 + 이름 정의

- 장점: 계산 가능성, 추적성, 유지보수성을 모두 만족한다.
- 단점: Excel 다운로드 구조가 한 시트 늘어난다.
- 판단: 최적안으로 채택한다.

## 11. 구현 플랜

### Phase 1: 설계 문서 확정

- 이 문서를 사용자 검토 대상으로 둔다.
- `REQ-20260625-01`의 다음 결정을 이 설계 문서 기준으로 갱신한다.

완료 기준:

- 세트 구성 단가 참조 방식이 문서에 명확히 정의된다.
- 구현 전 남은 결정사항이 식별된다.

### Phase 2: 내부 참조 모델 추가

- 세트상품 구성 데이터에서 안정적인 `priceRefName`을 생성한다.
- 세트 구성 단가 메타를 매출 수식 term에 포함한다.
- 화면 계산값은 기존과 동일해야 한다.

완료 기준:

- 기존 매출 숫자 결과가 변하지 않는다.
- 세트상품 항이 단가 참조 메타를 갖는다.

### Phase 3: 화면 수식 표시 개선

- 상단 수식 표시에서 세트 구성 단가를 `세트가(...)` 토큰으로 표시한다.
- hover/click으로 출처 상세를 확인할 수 있게 한다.

완료 기준:

- `BL11` 선택 시 `21040` 숫자만 보이지 않는다.
- 사용자가 `P00000YS/A -> P00000HT/A` 출처를 확인할 수 있다.

### Phase 4: Excel 다운로드 개선

- `세트상품구성` 시트를 생성한다.
- 세트 구성 단가 셀에 이름 정의를 생성한다.
- BL 매출 수식에서 세트상품 항은 이름 정의를 참조한다.

완료 기준:

- Excel 수식에 `BG11*21040` 같은 세트 구성 단가 literal이 남지 않는다.
- Excel 계산 결과는 기존 결과와 일치한다.
- 보조 시트에서 참조명과 단가 출처를 확인할 수 있다.

### Phase 5: 모달 변경 연동 검증

- 세트상품 구성 편집 모달에서 세트가 변경 시 화면 수식과 Excel 다운로드 수식/값이 갱신되는지 검증한다.

완료 기준:

- 모달 세트가 변경 전후 매출 결과가 기대대로 바뀐다.
- Excel 이름 정의는 같은 참조명을 유지하고 참조 셀 값만 바뀐다.

## 12. 회귀 테스트 계획

### 12.1 화면 E2E

- `BL11` 선택
- 수식 표시에서 `21040` literal이 직접 노출되지 않는지 확인
- 세트가 토큰에서 `P00000YS/A -> P00000HT/A`, `₩21,040` 출처 확인

### 12.2 Excel 다운로드 E2E

- Excel 다운로드
- `BL11` 수식 확인
- `BG11*21040`이 없어야 한다.
- `BG11*SET_P00000YS_A_P00000HT_A_PRICE` 같은 이름 참조가 있어야 한다.
- 이름 정의가 `세트상품구성` 시트의 올바른 세트가 셀을 가리켜야 한다.
- Excel 계산 결과가 기존 기대값과 일치해야 한다.

### 12.3 모달 편집 E2E

- `P00000YS / A` 세트상품 구성 모달 열기
- `P00000HT / A` 세트가를 `21040`에서 다른 값으로 변경
- 화면 매출과 수식 설명 갱신 확인
- Excel 다운로드 후 보조 시트 값과 BL 수식 계산 결과 확인
- 취소 시 변경이 반영되지 않는지도 확인

## 13. 남은 결정사항

1. `세트상품구성` 시트를 기본 표시할지, 숨김 처리할지
   - 권장: 기본 표시
2. 화면 수식에서 Excel 이름 정의를 그대로 보여줄지, 사용자 친화 토큰을 보여줄지
   - 권장: 사용자 친화 토큰 + 상세에서 참조명 표시
3. 전환상품 단가도 같은 방식으로 확장할지
   - 권장: 이번 범위는 세트상품 구성 단가로 제한하고, 전환상품 단가 참조는 별도 요구사항으로 분리
4. 이름 정의 충돌 시 suffix 규칙
   - 권장: 구성 id 기반 suffix 사용

## 14. 최종 권고

이번 요구사항은 `보조 시트 + Excel 이름 정의 + 화면용 설명 수식` 방식으로 구현한다.

이 방식은 단순히 숫자를 숨기는 것이 아니라, 세트 구성 단가가 어디서 왔고 어떤 계산에 쓰이는지 화면과 Excel 양쪽에서 추적 가능하게 만든다. 구현 범위는 크지만, 매출 계산의 데이터 무결성과 장기 유지보수성을 기준으로 보면 가장 안전하다.
