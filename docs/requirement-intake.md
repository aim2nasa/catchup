# 요구사항 인박스

## 목적

새 요구사항, 업무 규칙, 인터뷰 확인사항, cafe24 검증 중 발견된 문제를 먼저 기록하는 문서다.

이 문서에 적었다고 바로 구현하거나 PRD/TRD/UI에 반영되는 것은 아니다. 승인된 항목만 설계 문서로 승격한다.

## 운영 원칙

- 사용자 원문과 업무 맥락을 함께 남긴다.
- 엑셀 분석, cafe24 검증, 작성자 인터뷰, UI 설계 중 나온 요구를 모두 기록한다.
- 요구사항은 PRD/TRD/UI/UX/인터뷰/보류로 분류한다.
- 구현이 필요한 항목은 별도 작업 단위로 분리한다.

```markdown
- 우선순위: P0 / P1 / P2 / P3
- 다음 결정:
```

## 현재 인박스

### REQ-20260523-01: 엑셀 레이아웃을 그대로 복제하지 않는다

- 상태: 반영 완료
- 출처: 사용자 설명
- 사용자 원문:
  > 엑셀은 참고하는 데이터이지만, 이 엑셀처럼 그대로 보여주는게 아니라 사용자가 쉽게 이해하고 파악할 수 있도록 결과를 내야 한다.
- 업무 맥락: 기존 엑셀은 업무 규칙을 이해하기 위한 참고자료다. 실제 시스템 화면은 엑셀의 셀 구조를 그대로 복제할 필요가 없다.
- 현재 문제: 엑셀형 교차표를 그대로 웹으로 옮기면 사용자가 핵심 결과, 불일치, 미확정 항목을 빠르게 파악하기 어렵다.
- 기대 결과: 월별 요약, L 기준 집계, 미확정 매핑, 불일치 항목을 먼저 보여주고 상세 U 옵션 내역은 펼쳐보는 구조로 설계한다.
- 영향 문서: `docs/prd-trd-ui-prompt-draft.md`
- 우선순위: P1
- 다음 결정: PRD/TRD/UI 프롬프트 초안에 반영했다.

### REQ-20260523-02: 요구사항 수용 구조를 둔다

- 상태: 반영 완료
- 출처: 사용자 설명
- 사용자 원문:
  > 새로운 요구사항이 생기면 이를 체계적으로 수용하는 구조를 추가하고 싶어.
  > 요구사항 -> PRD/TRD/UI/UX 이렇게 반영되는 체계적인 구조.
- 업무 맥락: 작성자 인터뷰, cafe24 검증, UI 설계 과정에서 새 요구사항이 계속 발견될 수 있다.
- 현재 문제: 새 요구를 바로 설계나 구현에 섞으면 범위가 흔들리고 결정 근거가 사라진다.
- 기대 결과: 요구사항 인박스에 먼저 기록하고, 승인된 항목만 PRD/TRD/UI/UX에 승격한다.
- 영향 문서: `docs/requirements-to-design-process.md`, `docs/requirement-intake.md`, `docs/prd-trd-ui-prompt-draft.md`
- 우선순위: P1
- 다음 결정: 공통 프로세스 문서와 인박스 문서를 생성했다.

### REQ-20260624-01: Cafe24 조회값의 미조회/0/기준값 상태를 보존한다

- 상태: TRD 후보 / UI 후보 / UX 후보 / 데이터 검증 후보
- 출처: 사용자 설명 / UI 검토 / cafe24 검증
- 사용자 원문:
  > 값 읽을 수 없으면 0으로 표시하면 안돼. 이렇게 0으로 표시를 하면 실제값으로 오해를 하게 돼!!
  > 절대로 이렇게 표시하면 안돼. 값을 못갖고 온것과 읽은값을 확실하게 구분해서 표시가 되어야 돼.
  > 매우 매우 중요한 원칙이다.
  >
  > 직접판매셀만 값을 읽어오는 것은 아니야. 다른 셀들도 읽어와. 너 지금 문제를 너무 협소하게 판단해.
  > cafe24에서 읽어오는 모든 값들에 적용되어야 하는 규칙이야!!!
- 업무 맥락:
  `상품코드` 페이지에 `세트할인 구조설계` 탭의 L상품을 추가하면서, Cafe24 응답에 없는 상품/옵션의 직접판매 수량이 0처럼 보이는 문제가 드러났다. 이 문제는 직접판매 셀에 한정되지 않고 Cafe24에서 읽어오는 모든 값과 계산 결과, Excel 다운로드까지 영향을 준다.
- 현재 문제:
  조회 실패, 기준표 보강값, 실제 Cafe24 조회값 0이 같은 UI/Excel 표현으로 섞이면 사용자가 판매수량, 매출, 합계, 기준값을 잘못 판단할 수 있다. 특히 미조회 값을 0으로 표시하거나 계산하면 데이터 무결성 문제가 된다.
- 기대 결과:
  - `0`은 Cafe24에서 실제로 읽은 값이 0일 때만 표시한다.
  - Cafe24에서 읽지 못한 값은 별도 미조회 상태로 표시하고 0으로 계산하지 않는다.
  - 기준표/로컬 fallback 값은 Cafe24 조회값과 구분한다.
  - 상품명, 옵션명, 단가, 직접판매, 매핑 수량, 총판매, 매출, 소계, 합계 등 Cafe24 조회 기반 값 전체에 상태/출처가 보존된다.
  - 화면과 Excel 다운로드에서 동일한 업무 맥락이 유지된다.
  - Excel 계산식은 텍스트 상태값으로 깨지지 않으며, 미조회 포함 합계는 `미조회 제외 합계`임을 알 수 있다.
- 영향 문서:
  `docs/cafe24-read-value-state-policy.md`, 향후 TRD/UI/UX 설계 문서, Excel 다운로드 규칙, E2E 검증 기준
- 우선순위: P0
- 다음 결정:
  상세 정책 초안은 `docs/cafe24-read-value-state-policy.md`에 기록했다. 구현 전 아래 사항을 승인해야 한다.
  1. 화면의 좁은 숫자 셀에서 미조회 표시 방식
  2. Excel 상태 보존 방식(상태 컬럼/주석/범례)
  3. 기존 Excel 좌표계 유지 범위
  4. 기준표 단가의 계산 사용 조건
  5. 상품코드 페이지 우선 적용인지 공통 데이터 모델 확장인지
