## 로컬 개발 (Windows)

코드 고치면서 hot reload로 작업할 때.

### 최초 1회

```powershell
# 저장소 clone
git clone https://github.com/aim2nasa/catchup.git D:\catchup
cd D:\catchup

# Python 의존성
py -m pip install --upgrade fastapi uvicorn requests openpyxl python-dotenv

# Node 의존성
cd frontend
npm install
cd ..

# 환경변수
copy .env.example .env
# .env 편집하여 cafe24 자격증명 채우기
```

### cafe24 토큰 발급 (최초 1회)

```powershell
# 브라우저에서 OAuth 인증 → code 받음
# https://lycon.cafe24api.com/api/v2/oauth/authorize?...

py python\cafe24\tests\cafe24_token.py
# 프롬프트에 code 붙여넣고 엔터 → token.json 자동 저장 + Windows 작업 스케줄러 자동 등록
```

### 매번 (개발 모드, 권장)

프론트와 백엔드를 한 번에 실행한다. Vite는 `127.0.0.1:5173`, FastAPI는
`127.0.0.1:8000`에 고정된다.

```powershell
cd D:\catchup
npm run dev
```

→ 브라우저로 **http://127.0.0.1:5173/catchup/** 접속.

### 매번 (개발 모드, 수동 조사)

문제 조사처럼 서버를 분리해서 봐야 할 때도 사용자는 루트 통합 실행을 기본으로 사용한다.
frontend 단독 실행은 백엔드 누락으로 HTTP 502를 만들 수 있으므로 `npm run dev:frontend`와 직접 Vite 실행 모두 차단되어 있다.
이미 5173 포트가 점유된 경우에도 통합 실행기는 `/catchup/api/version` 프록시 health를 확인한다.
프록시가 건강하지 않으면 stale frontend로 판단하고 backend를 남기지 않은 채 중단한다.

**권장**
```powershell
cd D:\catchup
npm run dev
```

→ 브라우저로 **http://127.0.0.1:5173/catchup/** 접속.

### 정지

각 터미널에서 `Ctrl+C`.

## tars 서버 배포 (Linux)

**서버**: `tars.giize.com` / Tailscale `100.110.215.65` / 사용자 `rossi`
**경로**: `/home/rossi/catchup`
**백엔드 포트**: `8300` (host `0.0.0.0`)
**관리**: PM2 (서비스명 `catchup`)
**외부 접속**: `https://tars.giize.com/catchup/` (nginx reverse proxy + Let's Encrypt TLS)

```
[Internet] ──HTTPS─▶ tars:443 (nginx) ──proxy_pass──▶ tars:8300 (catchup uvicorn)
```

### 최초 부트스트랩

#### 1) 코드 / 자격 증명 / 환경변수

```bash
# 서버 접속
ssh rossi@100.110.215.65

# 저장소 clone
cd ~
git clone https://github.com/aim2nasa/catchup.git
cd catchup

# .env / token.json 은 로컬에서 scp로 복사 (또는 서버에서 직접 작성)
# 로컬 Windows에서:
#   scp D:\catchup\.env rossi@100.110.215.65:~/catchup/.env
#   scp D:\catchup\python\cafe24\tests\token.json rossi@100.110.215.65:~/catchup/python/cafe24/tests/

# 호스트/포트 환경변수 추가 (서버 전용)
echo "CATCHUP_HOST=0.0.0.0" >> .env
echo "CATCHUP_PORT=8300" >> .env
```

#### 2) 배포 스크립트 (venv + pip + npm + build + PM2)

```bash
./deploy.sh
```

`deploy.sh` 가 실행 권한(+x)으로 git에 박혀있어 별도 `chmod +x` 불필요.

#### 3) nginx reverse proxy (외부 HTTPS 접속용, 1회 설정)

이미 tars 에는 `tars.giize.com` 의 nginx + Let's Encrypt 인증서가 운영 중.
catchup 용 `/catchup/` location 만 추가:

```bash
sudo bash scripts/setup_tars_nginx.sh
```

스크립트 동작 (멱등):
1. `/etc/nginx/sites-enabled/tars` 백업 (timestamp 부여)
2. `BEGIN catchup-block` ~ `END catchup-block` 마커 사이를 `docs/nginx-catchup.conf` 로 갱신/삽입
3. `nginx -t` 검증 → 실패 시 백업 자동 롤백
4. `systemctl reload nginx`
5. `https://tars.giize.com/catchup/api/version` 외부 검증

성공 시 `✅ 성공` 메시지 + 버전 JSON 출력.

> 새 nginx 설정 변경(예: 헤더 추가, body 한도 변경)이 필요하면 `docs/nginx-catchup.conf` 만 수정 후 다시 `sudo bash scripts/setup_tars_nginx.sh` 실행하면 됨 (마커 사이만 교체).

#### 4) 토큰 자동 갱신 (cron)

```bash
# keepalive 래퍼 작성
cat > ~/catchup/keepalive_cron.sh <<'EOF'
#!/usr/bin/env bash
cd ~/catchup
.venv/bin/python python/cafe24/tests/keepalive.py >> ~/catchup/keepalive.log 2>&1
EOF
chmod +x ~/catchup/keepalive_cron.sh

# crontab에 매주 월 09:00 등록
( crontab -l 2>/dev/null | grep -v "catchup/keepalive" ; echo "0 9 * * 1 ~/catchup/keepalive_cron.sh" ) | crontab -

# 확인
crontab -l | grep catchup
```

### 접속

| 경로 | URL | 비고 |
|---|---|---|
| **외부 HTTPS** | **https://tars.giize.com/catchup/** | 권장 (어디서든 접속) |
| 외부 API | https://tars.giize.com/catchup/api/version | 헬스체크용 |
| Tailscale 직접 | http://100.110.215.65:8300 | 사내망/디바이스 한정 |
| Tailscale API | http://100.110.215.65:8300/api/version | 디버깅 |

⚠️ React 앱은 `base: '/catchup/'` 로 빌드되어 모든 자산/라우팅이 `/catchup/` prefix 기준. nginx가 prefix를 제거하고 백엔드(8300)로 보내며, 백엔드는 prefix 없이 `/api/...`만 받는다.

## 업데이트 / 재배포

로컬에서 변경 → 커밋 → 푸시 → 서버 배포.

### 로컬

```powershell
cd D:\catchup
git add .
git commit -m "..."
git push
```

### 서버

```bash
# 로컬에서 한 줄로
ssh rossi@100.110.215.65 'cd ~/catchup && ./deploy.sh'
```

`deploy.sh`가 자동으로:
1. `git pull --ff-only`
2. Python 의존성 갱신 (`.venv/bin/pip install ...`)
3. `npm install` (lock 변경 시) + `npm run build`
4. `pm2 restart catchup --update-env` (없으면 start)

## 버전 체계

`git describe --always --dirty --tags` 기반 자동 산출.

- 마일스톤만 수동 태그: `git tag v0.2.0`
- 커밋마다 자동 증가: `v0.1.0-N-g<sha>` (N=태그 이후 커밋 수)
- 미커밋 변경 있으면 끝에 `-dirty`
- 웹 UI footer + `/api/version` 엔드포인트로 노출

## 자격증명 / 토큰 관리

| 파일 | 위치 | 내용 | 커밋 |
|---|---|---|---|
| `.env` | 프로젝트 루트 | cafe24 OAuth 자격 (CLIENT_ID/SECRET, MALL_ID, REDIRECT_URI, SCOPE) + 호스트/포트 | ❌ (gitignore) |
| `python/cafe24/tests/token.json` | 동일 경로 | access_token / refresh_token / expires_at | ❌ (gitignore) |

`.env.example`이 키 목록 템플릿. 커밋 절대 금지.

토큰 만료 정책:
- access_token: 2시간 (자동 갱신)
- refresh_token: 2주 (사용 시마다 새로 발급되어 갱신)
- 2주 이상 미사용 시 → refresh도 죽음 → 브라우저 OAuth 재인증 필요 (`cafe24_token.py`)

자동 갱신:
- Windows: 작업 스케줄러 `cafe24-token-keepalive` (매주 월 09:00)
- Linux (tars): cron `0 9 * * 1 ~/catchup/keepalive_cron.sh`

## 트러블슈팅

### `address already in use`

다른 프로세스가 포트 점유. 다른 포트 사용:
```bash
# .env에 추가
echo "CATCHUP_PORT=8400" >> .env
pm2 restart catchup --update-env
```

### `externally-managed-environment` (Ubuntu 24.04)

`pip install` 직접 실행 시 PEP 668. `deploy.sh`가 venv를 자동 생성하므로 그것을 사용:
```bash
cd ~/catchup
./deploy.sh   # .venv 자동 생성/사용
```

### cafe24 401 / 토큰 만료

```bash
# 로그 확인
tail -n 30 ~/catchup/keepalive.log

# 수동 갱신 시도
cd ~/catchup
.venv/bin/python python/cafe24/tests/keepalive.py
```

위가 실패하면 (refresh도 죽었으면): 브라우저 OAuth 재인증 → 새 token.json 받아서 scp로 서버에 복사.

### Frontend 빌드 후에도 옛 UI 보임

브라우저 캐시. **Ctrl+Shift+R** (하드 새로고침).

### Playwright 테스트 실패: cafe24 호출 시나리오만

토큰 만료 가능성. 위 "cafe24 401" 절차 따라 갱신 후 재실행.

### 회귀 테스트가 갑자기 다 깨짐

cafe24 응답 구조가 변경되었을 가능성. fixtures를 새로 캡처:
```bash
# tests/fixtures/cafe24_*.json 갱신
py -c "
import json, requests, sys
sys.path.insert(0, 'python/cafe24/tests')
from cafe24_auth import get_access_token, MALL_ID
base = f'https://{MALL_ID}.cafe24api.com/api/v2/admin'
h = {'Authorization': f'Bearer {get_access_token()}'}
# ... 각 fixture 다시 저장
"
```

또는 의도된 변경이라면 테스트 expected를 함께 갱신 후 커밋.

### tars: `git pull` 실패 — `Your local changes to the following files would be overwritten by merge: deploy.sh`

Linux에서 `chmod +x` 후 git diff 에 mode 변경이 남는 경우. 한 번만:
```bash
cd ~/catchup
git checkout -- deploy.sh
git pull
```
이후엔 git index 에 +x 가 박혀있어 다시 발생하지 않음.

### tars: `https://tars.giize.com/catchup/` 가 Redmine 404 페이지로 감

nginx에 catchup location이 아직 안 들어간 상태. 다음을 실행:
```bash
cd ~/catchup
git pull
sudo bash scripts/setup_tars_nginx.sh
```

### tars: nginx reload 후에도 `/catchup/` 응답 없음

```bash
# 백엔드 살아있는지
pm2 status catchup
curl -sf http://127.0.0.1:8300/api/version

# nginx 설정에 catchup-block이 들어갔는지
sudo grep -A2 "catchup-block" /etc/nginx/sites-enabled/tars

# nginx 에러 로그
sudo tail -n 30 /var/log/nginx/error.log
```

### React 빌드 후에도 옛 화면이 보임 (외부 URL)

브라우저 캐시. **Ctrl+Shift+R** (하드 새로고침). 그래도 안 되면 dist 가 갱신되었는지 확인:
```bash
ssh rossi@100.110.215.65 'ls -la ~/catchup/frontend/dist/index.html ~/catchup/frontend/dist/assets/*.js'
```
`./deploy.sh` 가 매번 dist 를 갱신하지만, `npm install` 단계에서 lock이 안 바뀐 경우 의존성 install 은 건너뛰니 코드 변경만 반영됨.
