## 로컬 개발 (Windows)

코드 고치면서 hot reload로 작업할 때.

### 최초 1회

```powershell
# 저장소 clone
git clone https://github.com/aim2nasa/catchup.git D:\catchup
cd D:\catchup

# Python 의존성
py -m pip install --upgrade fastapi uvicorn requests openpyxl python-dotenv

# Node 의존성
cd frontend
npm install
cd ..

# 환경변수
copy .env.example .env
# .env 편집하여 cafe24 자격증명 채우기
```

### cafe24 토큰 발급 (최초 1회)

```powershell
# 브라우저에서 OAuth 인증 → code 받음
# https://lycon.cafe24api.com/api/v2/oauth/authorize?...

py python\cafe24\tests\cafe24_token.py
# 프롬프트에 code 붙여넣고 엔터 → token.json 자동 저장 + Windows 작업 스케줄러 자동 등록
```

### 매번 (개발 모드, 터미널 2개)

**터미널 1 — backend**
```powershell
py D:\catchup\backend\main.py
```
http://127.0.0.1:8000 에 백엔드 가동.

**터미널 2 — frontend**
```powershell
cd D:\catchup\frontend
npm run dev
```
http://127.0.0.1:5173 에 React dev 서버. `/api` 호출은 Vite proxy로 8000번에 자동 포워딩.

→ 브라우저로 **http://127.0.0.1:5173** 접속.

### 정지

각 터미널에서 `Ctrl+C`.

## 업데이트 / 재배포

로컬에서 변경 → 커밋 → 푸시 → 서버 배포.

### 로컬

```powershell
cd D:\catchup
git add .
git commit -m "..."
git push
```

### 서버

```bash
# 로컬에서 한 줄로
ssh rossi@100.110.215.65 'cd ~/catchup && ./deploy.sh'
```

`deploy.sh`가 자동으로:
1. `git pull --ff-only`
2. Python 의존성 갱신 (`.venv/bin/pip install ...`)
3. `npm install` (lock 변경 시) + `npm run build`
4. `pm2 restart catchup --update-env` (없으면 start)

## 버전 체계

`git describe --always --dirty --tags` 기반 자동 산출.

- 마일스톤만 수동 태그: `git tag v0.2.0`
- 커밋마다 자동 증가: `v0.1.0-N-g<sha>` (N=태그 이후 커밋 수)
- 미커밋 변경 있으면 끝에 `-dirty`
- 웹 UI footer + `/api/version` 엔드포인트로 노출

## 자격증명 / 토큰 관리

| 파일 | 위치 | 내용 | 커밋 |
|---|---|---|---|
| `.env` | 프로젝트 루트 | cafe24 OAuth 자격 (CLIENT_ID/SECRET, MALL_ID, REDIRECT_URI, SCOPE) + 호스트/포트 | ❌ (gitignore) |
| `python/cafe24/tests/token.json` | 동일 경로 | access_token / refresh_token / expires_at | ❌ (gitignore) |

`.env.example`이 키 목록 템플릿. 커밋 절대 금지.

토큰 만료 정책:
- access_token: 2시간 (자동 갱신)
- refresh_token: 2주 (사용 시마다 새로 발급되어 갱신)
- 2주 이상 미사용 시 → refresh도 죽음 → 브라우저 OAuth 재인증 필요 (`cafe24_token.py`)

자동 갱신:
- Windows: 작업 스케줄러 `cafe24-token-keepalive` (매주 월 09:00)
- Linux (tars): cron `0 9 * * 1 ~/catchup/keepalive_cron.sh`

## 트러블슈팅

### `address already in use`

다른 프로세스가 포트 점유. 다른 포트 사용:
```bash
# .env에 추가
echo "CATCHUP_PORT=8400" >> .env
pm2 restart catchup --update-env
```

### `externally-managed-environment` (Ubuntu 24.04)

`pip install` 직접 실행 시 PEP 668. `deploy.sh`가 venv를 자동 생성하므로 그것을 사용:
```bash
cd ~/catchup
./deploy.sh   # .venv 자동 생성/사용
```

### cafe24 401 / 토큰 만료

```bash
# 로그 확인
tail -n 30 ~/catchup/keepalive.log

# 수동 갱신 시도
cd ~/catchup
.venv/bin/python python/cafe24/tests/keepalive.py
```

위가 실패하면 (refresh도 죽었으면): 브라우저 OAuth 재인증 → 새 token.json 받아서 scp로 서버에 복사.

### Frontend 빌드 후에도 옛 UI 보임

브라우저 캐시. **Ctrl+Shift+R** (하드 새로고침).

### Playwright 테스트 실패: cafe24 호출 시나리오만

토큰 만료 가능성. 위 "cafe24 401" 절차 따라 갱신 후 재실행.

### 회귀 테스트가 갑자기 다 깨짐

cafe24 응답 구조가 변경되었을 가능성. fixtures를 새로 캡처:
```bash
# tests/fixtures/cafe24_*.json 갱신
py -c "
import json, requests, sys
sys.path.insert(0, 'python/cafe24/tests')
from cafe24_auth import get_access_token, MALL_ID
base = f'https://{MALL_ID}.cafe24api.com/api/v2/admin'
h = {'Authorization': f'Bearer {get_access_token()}'}
# ... 각 fixture 다시 저장
"
```

또는 의도된 변경이라면 테스트 expected를 함께 갱신 후 커밋.
