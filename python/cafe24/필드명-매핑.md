# cafe24 필드명 매핑

cafe24 어드민 화면(한국어 라벨)과 OpenAPI 응답 필드의 1:1 매핑. 
엑셀이나 사람이 부르는 이름과 코드에서 다루는 키 이름이 달라서 생기는 혼란을 줄이기 위함.
실제 mall_id `lycon`의 product_no=21 (`P000000U`, "슈가스크럽 바디로션250ml") 응답을 기준으로 작성.

## 상품 (Product)

| 어드민 화면 | API 필드 | 형식 / 예 |
|---|---|---|
| 상품번호 | `product_no` | 정수 (예: `21`) — cafe24 내부 식별자 |
| 상품코드 | `product_code` | `P` + 7자리 = 총 **8자** (예: `P000000U`) |
| 자체 상품코드 | `custom_product_code` | 사용자 정의, 비어있는 경우 많음 |
| 상품명 | `product_name` | "슈가스크럽 바디로션250ml" |
| 옵션 사용 여부 | `has_option` | `T` (옵션 있음) / `F` (옵션 없음) |
| 진열상태 | `display` | `T` / `F` |
| 판매상태 | `selling` | `T` / `F` |

## 품목 (Variant)

| 어드민 화면 | API 필드 | 형식 / 예 |
|---|---|---|
| 품목코드 | `variant_code` | 상품코드 + 옵션 4자리 = 총 **12자** (예: `P000000U000Q`) |
| 자체 품목코드 | `custom_variant_code` | 사용자 정의, 자유 입력 |
| 옵션명 / 옵션값 | `options[].name` / `options[].value` | 예: `name="선택"`, `value="애플"` |
| 재고수량 | `quantity` | 정수 (음수 가능, 예: `-100`) |
| 안전재고 | `safety_inventory` | 정수 |
| 진열 | `display` | `T` / `F` |
| 판매 | `selling` | `T` / `F` |

## 코드 체계 정리

### 옵션이 있는 상품 (예: `P000000U`)
| 옵션 | variant_code |
|---|---|
| 애플 | `P000000U000Q` |
| 석류 | `P000000U000R` |
| 코코넛 | `P000000U000S` |
| 라벤더 | `P000000U000T` |
| 자몽(핑크) | `P000000U000U` |
| 망고 | `P000000U000V` |

→ 상품코드 1개가 **여러 variant_code를 가짐**. 엑셀 등에서 상품코드만 적혀 있으면 어느 옵션인지 알 수 없음.

### 옵션이 없는 상품
- 그래도 cafe24는 자동으로 variant 1개를 만들고 `variant_code = 상품코드 + "000A"` 부여.
- 예: `P0000BNL` → `P0000BNL000A` (옵션 없음, options 배열 비어 있음)
- 사실상 상품코드 = 단일 SKU 의미. 엑셀에 상품코드만 적혀 있어도 모호성 없음.

## 자동화 시 주의

- **상품코드만 있고 옵션이 여러 개인 행**: `has_option` 확인 → `T`이면 어느 variant인지 명세 필요.
- 일부 행은 한 셀에 여러 상품코드가 슬래시로 묶여 있음(예: `P0000BIF / P0000BLD / ...`) — 파싱 후 개별 조회.
- `quantity`가 음수일 수 있음 (재고 음수 = 과주문/오차).
- "자체 품목코드"(`custom_variant_code`)는 사내 코드 체계를 별도로 운영할 때 활용 가능.
